## How to keep the automation running for days

```bash
# One book at a time, forever, no sleep between books (picks up new manifest rows each pass):
.venv/Scripts/python -m automation.generate --limit 1 --loop

# Detached (PowerShell), survives terminal close:
Start-Process -WindowStyle Hidden -FilePath ".venv\Scripts\python.exe" -ArgumentList "-m","automation.generate","--limit","1","--loop"
```

Exponential backoff with jitter handles every rate limit and temporary error (LLM calls, search backends, page fetches); the pipeline never sleeps proactively.

Ctrl-C (or `Stop-Process`) stops between passes; the lock releases automatically; restarting resumes exactly where it stopped because completed notes are skipped and partial drafts are reused. New books are added by appending `(number, priority, category, subcategory, title, author)` entries to the curriculum data files and re-running `automation/curriculum.py` + `automation/build_docs.py`.

## Known limits and notes

- **Ox Alpha Free** is a reasoning model on a free tier: it can return empty content when its reasoning consumes the token budget, in which case the pipeline retries then falls back to NVIDIA.
- Free search endpoints (DuckDuckGo) rate-limit intermittently; the pipeline degrades gracefully (YaCy → ddgs → stdlib) and skips a book rather than crashing.
- Summary size: new notes target 4,000–8,000+ words (up to 15,000 for foundational works).
- `.env` is gitignored and holds no secret (Zen is keyless). An `NVIDIA_API_KEY` found in the shell environment enables the fallback; never commit it.
