# Book Manifest

> This file is the source of truth for one canonical Markdown file per included book.

## Manifest status

The vault is built from the **canonical 2,000-book curriculum**: a numbered, priority-tagged learning sequence (`S` = foundational, `A` = highly recommended, `B` = expansion/reference). The first 800 curriculum slots have been transcribed and deduplicated into the machine-readable manifest at `automation/manifest.csv` — currently **775 canonical books** across **12 pillars** (98 level-2 categories). The remaining slots (801–2000) will be transcribed the same way and picked up automatically by the pipeline.

Classification is four-level (Faceted / MECE): **Pillar** (level 1, folder) → **Category** (level 2, folder) → **Subcategory** (level 3, front matter) → **Tags/Theme** (level 4, front matter). The builder maps every old curriculum category into exactly one pillar and category via the MECE table in `automation/curriculum.py`.

The manifest is regenerated by the builder, never hand-edited:

```bash
.venv/Scripts/python -m automation.curriculum   # rebuilds manifest.csv + taxonomy
.venv/Scripts/python -m automation.build_docs   # rebuilds ALL-BOOKS.md + READING-ORDER.md
```

The curriculum source lives in `automation/curriculum_data_1.py` (001–400) and `automation/curriculum_data_2.py` (401–800); each entry is `(number, priority, category, subcategory, title, author)`. The builder:

- Normalizes titles and authors and generates unique slugs.
- Detects duplicates by title + author surname (25 removed so far, e.g. *Essentialism*, *The Structure of Scientific Revolutions*, *Man's Search for Meaning*, *Why Nations Fail*) and keeps one canonical row.
- Flags vague/non-book entries for review (0 currently pending).
- Assigns exactly one primary category and one primary subcategory per book.

## Canonical rules

- Normalize editions to one canonical work unless a new edition materially changes the work.
- Assign exactly one primary pillar, one primary category, and one primary subcategory.
- Store the book at `md/<pillar>/<NN-category>/<book-slug>.md`.
- Record the learning stage, prerequisites, publication year, and primary source in the note's front matter; the generator fills these from research.
- Record duplicates and excluded fiction instead of silently deleting the evidence.
- Validate author, title, publication year, category, and sources before writing a summary.
- Do not create a book file until its canonical manifest entry exists.

## Status fields

Each manifest row carries `status`: `planned` (awaiting generation), `draft`, or `complete`. The pipeline skips `complete` books, reuses partial drafts after crashes, and writes atomically — so the same book is never generated twice, even across days of unattended runs.

## Adding books

To add a book: append a `(number, priority, category, subcategory, title, author)` entry to the curriculum data file, run the two builder commands above, then run the generation pipeline. New rows are picked up automatically on the next loop pass.

See [[ALL-BOOKS]] for the full catalog and [[SUBCATEGORY-MAP]] for the taxonomy.
